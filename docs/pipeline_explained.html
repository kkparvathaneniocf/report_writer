The Report Robot

How a pile of lab PDFs becomes a finished DNV test report, and how we can always point to the exact spot every word, number and picture came from.

ea87bba6:p1:t2r1c1

The one big rule: every piece the robot puts in the report wears a name tag that says which paper, which page and which spot it came from. No tag, no trust.

The whole trip at a glance

Box of papers→ Sort→ Name tags→ Treasure map→ Four helpers→ Checker→ Glue into Word→ Receipts→ Grown-up signs

Step by step

1

A box of papers arrives

Think of it like

Someone hands the robot a box with six papers in it. Each paper knows one part of the story, but none of them knows all of it.

What really happens: the TR folder holds six PDFs: the test request, the fiber content file, the tensile machine report, the fabric certificate (COA), the infusion report and the specimen pictures.

data/raw/TR26_C0143/*.pdf
2

Sort the papers into drawers

Think of it like

Sorting socks: the robot reads the label on each paper and drops it in the right drawer. It also takes each paper's fingerprint. If even one dot on the paper changes later, the fingerprint changes too, so nobody can swap a paper secretly.

What really happens: each PDF gets a document type from its file name or first-page words (TR_REQUEST, FWF, MACHINE_TENSILE, COA, INFUSION, PICTURES) and a SHA-256 fingerprint.

pipeline/index.pyconfig/report_spec.yaml → documents
3

Put a name tag on every little piece

Think of it like

Cutting each paper into tiny Lego bricks and putting a sticker on every brick. The sticker says which paper, which page, and exactly where on the page the brick sat.

ea87bba6:p1:t2r1c1
paper fingerprint
(fiber content file)		page 1table 2row 1column 1

What really happens: five kinds of bricks get tags: whole pages (:p2), text lines (:l6), table cells (:t2r1c1), photos (:i1) and drawn figures such as stress-strain curves (:f1). Each tag also stores the box around the brick on the page. Everything goes into a small database.

output/…/index.sqlite
4

Read the treasure map

Think of it like

A treasure map that says: "The fabric batch number is hidden in the COA paper, right after the words Batch N°." Every empty spot in the report has its own line on the map, so the robot always knows which drawer to open.

What really happens: the report spec lists every blank in the DNV template and where its answer lives. This is retrieval, but aimed: the robot never rummages through all papers at once. That keeps answers exact and the AI's reading small.

config/report_spec.yamldata/templet/dnv_poc_template.docx
5

Four helpers fetch the pieces

The Copier

Copies words and numbers exactly as written, like "24B1187" or a whole results table. Never changes a letter.

VERIFIED

The Calculator

Works out the average, spread (SD), CV, highest and lowest. It keeps a list of every number it used, like showing its homework.

COMPUTED

The Photographer

Takes snapshots of whole pages (COA, infusion report) and cuts out photos and curves by reading their captions. Each picture gets its own fingerprint.

VERIFIED

The Storyteller (Gemma)

Writes short sentences, like the product description. It only reads one drawer and must point at the tags it used. Storytellers can make things up, so a grown-up always checks.

NEEDS_REVIEW

What really happens: label lookups and table reading are plain code; statistics are plain code; Gemma 4 runs locally through Ollama with thinking switched off and must cite tag IDs. Numbers in results tables never come from the AI.

pipeline/extract.pypipeline/images.pypipeline/llm.py
6

The checker looks twice

Think of it like

A friend who checks your homework: "You said the answer is on this brick. Let me look. Yes, it's really there." If two papers give different answers, the checker raises a hand. If nobody can find the answer, it says so out loud instead of guessing.

What really happens: every copied value must appear in the text of the tag it cites. If the AI cites a tag that doesn't exist, it is flagged. Cross-checks compare sources: the COA says batch 24B1187, the infusion report says 24B1178, so the value is marked CONFLICT.

7

Glue everything into the Word report

Think of it like

Filling in a sticker book. Each blank gets its piece, and next to it the robot sticks a little note: "I came from the COA, page 1, line 6." Anything that needs a grown-up's eye gets a bright color.

What really happens: blanks such as {{fabric_batch}} in the DNV template are replaced while keeping Word formatting. Table rows are copied once per specimen, pictures go into the appendices, and every value gets a Word comment with its source and tag.

pipeline/render.pyoutput/…/report.docx
8

Keep all the receipts

Think of it like

Keeping the receipt for everything you bought. Later, anyone can ask "where did this come from?" and the robot shows the receipt, with a little photo of the exact spot on the paper.

What really happens: a provenance file lists every value with its status, method, cited tags, inputs and AI model version. Cropped PNGs show each cited spot. The trace command answers the question for one value.

output/…/provenance.jsonoutput/…/evidence/*.pngoutput/…/images/*.png
9

A grown-up checks and signs

Think of it like

The robot can build the whole sticker book, but it is never allowed to sign it. A person looks at every colored spot, fills in the yellow parts, and then signs.

What really happens: the yellow fields (requester, test period, writer, validator, dates, distribution) stay manual. Turquoise, pink and red values are reviewed before release. Nothing is signed automatically.

What the colors in the Word report mean

no color

Copied exactly or calculated, and checked. Safe, but still readable in the note.

turquoise

Written by the AI storyteller. Read it and compare with the cited source.

pink

Two papers disagree. Decide which one is right.

red

Missing, or not built yet. Find it or fill it in by hand.

yellow

Always typed by a person (from the template). The robot never touches it.

Try it yourself

python run_poc.py                        # build the report without the AI
python run_poc.py --llm --model gemma4:26b  # with Gemma via Ollama
lab-report trace fabric_batch            # where did this value come from?

Results land in output/TR26_C0143/: report.docx, provenance.json, index.sqlite, evidence/ and images/.

What the robot can't do yet

  • Calculate characteristic values (Rk) per DNVGL-ST-0376 and GL2010.
  • Read scanned papers. That needs OCR or Gemma's picture reading.
  • Read real machine reports. Each machine's layout needs its own reader, built from real sample PDFs.
